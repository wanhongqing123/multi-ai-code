# 本地 ONNX 图像与视频遮挡修复调研

调研日期：2026-10-11。这里的“去水印”指用户明确要求、且有权编辑的可见局部覆盖物修复。修复模型根据周围画面**推测**被遮住的内容，不能还原原始像素；不能用生成的结果证明原图本来是什么样。

## 历史基线（调研起点）

调研开始时，`media_remove_watermark` 接受 1–4 个像素矩形，经过 FFprobe 检查后用 FFmpeg `delogo` 输出新文件。它保留源文件和音频，但大矩形会误伤伸进遮挡区域的手。用户后来明确要求移除这条 Agent 执行路径，改用本地 ONNX 与临近干净帧补画；当前 iOS 实现见文末。

## 候选模型

| 模型 | 本地 ONNX 状态 | 适合的输入 | 接入判断 |
|---|---|---|---|
| [MI-GAN](https://github.com/Picsart-AI-Research/MI-GAN) | 作者提供完整预/后处理管线的 [ONNX 导出脚本及预转换模型](https://github.com/Picsart-AI-Research/MI-GAN#for-developers) | 图片、视频帧中较小的遮挡区域 | **第一候选**。作者针对移动端设计；输入 RGB 图与二值 mask。代码和权重各有 [MIT 许可](https://github.com/Picsart-AI-Research/MI-GAN/blob/main/LICENSE-WEIGHTS)，但仍须保留许可文本。需在本项目的 iOS/Android/桌面 ONNX Runtime 构建上实跑，不能仅凭 `.onnx` 文件推断可用。 |
| [LaMa](https://github.com/advimman/lama) / [Carve LaMa-ONNX](https://huggingface.co/Carve/LaMa-ONNX) | 原作者发布 PyTorch 实现；Carve 发布第三方 ONNX 移植。推荐的 `lama_fp32.onnx` 为固定 512×512、opset 17 | 面积较大、背景纹理复杂的单张图 | **备选基线**。需核实第三方权重来源、许可和实机内存/耗时；不应把它称为官方 ONNX 版本。 |
| [ProPainter](https://github.com/sczhou/ProPainter) | 官方提供 PyTorch 视频修复流程，未找到官方可直接部署的 ONNX 成品 | 移动遮挡、跨帧一致性要求高的视频 | **研究对照，不直接进 App**。官方示例的显存需求较高，且 [代码/模型许可限非商业用途](https://github.com/sczhou/ProPainter/blob/main/LICENSE)。 |
| [E2FGVI-HQ](https://github.com/MCG-NKU/E2FGVI) | 官方为 PyTorch/CUDA 推理；未找到官方已验证的 ONNX 导出 | 多帧视频修复 | **研究对照**。其[许可也限非商业用途](https://github.com/MCG-NKU/E2FGVI#license)，不适合直接随商业 App 分发。 |

[SAM 的官方 ONNX 导出](https://github.com/facebookresearch/segment-anything#onnx-export)仅覆盖提示式 mask 解码器；图像编码器及自动识别仍需额外实现。它可以辅助用户圈选或细化遮挡区域，**不是**去水印修复模型，也不会自动理解“哪个区域是水印”。首版沿用已有矩形输入更直接。

## 推荐实验顺序

1. 先用 MI-GAN 在桌面、iOS 真机、Android 真机各验证一次：读取图像 + 二值 mask → ONNX Runtime → 新图。作者管线规定 mask 中 **255 是已知区域、0 是待修复区域**，与常见“白色表示待修复”的约定相反；适配时必须显式转换。
2. 用同一批用户有权编辑的样本，对比现有 `delogo` 与 MI-GAN 的静态图质量、内存、单帧耗时、包体大小。检查透明/半透明覆盖物、边缘、移动背景、人物轮廓。
3. 视频先做短片试验：按原有时间段生成稳定 mask，逐帧修复后合成，沿用原音轨；检查闪烁、运动物体断裂和画面色彩空间。逐帧图像修复**不等于**时序一致的视频模型，质量未过关前不标为正式视频能力。
4. 只有 MI-GAN 对大面积遮挡不够用、且实机资源允许时，再测第三方 LaMa ONNX。视频跨帧质量若仍不够，再单独评估许可允许且有可部署推理路径的视频模型。

以上是调研开始时的实验顺序；后续已经按样本结果调整了选型，见下文。

## 字幕移除也适用，但先区分字幕类型

- **独立字幕轨**：字幕没有写入视频像素，直接在封装时不映射字幕轨即可；不需要 ONNX，也不需要重建画面。
- **画面内硬字幕**：MI-GAN、LaMa 这类遮挡修复模型可以处理，但必须先给出每帧字幕的遮罩。固定在底部的字幕可从用户框选区域开始；位置、行数、出现时间不断变化时，还需要字幕定位/跟踪与时间段管理。遮罩只覆盖文字及必要边缘，避免把人物、景物整条抹掉。
- **视频质量**：逐帧单图模型可能造成背景闪烁、运动物体断裂；字幕压住人物脸部或复杂动态背景时，模型只能推测，不能保证还原。需要用短片对比原音频、帧率、时序一致性后，才能作为正式视频功能开放。

调研时的旧版 `media_remove_watermark` 只支持矩形 `delogo`，没有自动识别硬字幕的能力；这条旧 Agent 路径已移除。

## 实测：14.7 秒竖屏 MOV 样本

用户提供的样本为 H.264/AAC、1452×2532、约 29.86 fps，没有字幕轨。画面中是左上角固定的“AI 生成”、右下角固定字样，以及在左侧、右上、右下轮换位置的抖音标识；因此本样本检验的是**动态水印**，不能直接代表底部对白字幕的效果。

在同一矩形区域对第 3 秒左侧标识、第 0.5 秒右下角重叠标识做单帧对比：

| 方法 | 左侧天空 | 右下模糊底栏 | Mac CPU 预检耗时 |
|---|---|---|---|
| 原有 `delogo` | 可清除，平滑背景质量可接受 | 可清除，保留模糊底栏 | 1 秒短片编码约 0.4 秒；不是单帧推理耗时 |
| MI-GAN ONNX | 可清除，与 `delogo` 差距小 | 矩形遮罩出现细色线；改用字形遮罩后出现不自然的纹理 | 约 0.27 秒/帧，模型约 27 MB |
| LaMa ONNX | 单帧较干净 | 单帧较干净 | 512×512 区域约 2.4 秒/帧，模型约 198 MB |
| 从另一个无标识帧复制背景 | 左侧天空单帧可清除 | 固定字样没有干净参考帧 | 本地像素操作很快，但需可靠的选帧、配准和跨帧稳定性验证 |

这些速度是在 Mac 上对样本做的预检，**不是 iOS/Android 真机性能**。MI-GAN 已做约 1 秒、30 帧的本地连续处理预检；LaMa 只做了单帧。尚未完成整片遮罩跟踪、真机推理、音频保留及出片验收，不能宣称某个方法已具备可交付的移动端视频能力。此样本的决定性缺口是**标识随时间换位置**；仅替换修复模型不能解决这一问题。

用户明确要求全部移除后，另做了一份**样本专用的 Mac 离线验证片**：逐帧识别移动标识在左侧、右上或右下的位置；左侧和右上从相邻无遮挡帧借背景，按时间插值、逐帧匹配颜色并羽化边缘；两处固定字样及右下模糊底栏用区域填充。处理了 438 帧，输出 H.264，原 AAC 音轨直接复制；最终 14.7 秒片可完整解码。转场第 118 帧左右和右上标识同时出现，验证时按双区域处理，不能假设每帧只出现一个位置。逐帧扫描五处目标区域未再检出高亮文字。产物位于用户本机 `~/Movies/MaiChat/watermarks-removed-2026-10-11.mp4`，并已通过 IM 发给用户检查。

这份产物验证了**该样本**可用“位置检测 + 临近干净帧补画 + 固定字样填充”处理；它使用 Mac 离线脚本，并未变成 App 功能。移动端实现要把同一策略移入共享 C++ 视频流水线，逐帧生成位置与遮罩，选取无遮挡参考帧，处理摄像机运动、人物遮挡和不存在干净参考帧的情况，并在 iOS/Android 真机上检验内存、发热、后台持续性及音画同步。MI-GAN 可作为复杂局部画面的候选兜底，但本样本右下角实测伪影说明不能自动替换为它；LaMa 的模型体积与单帧耗时也不适合直接作为手机默认路径。

按用户要求又生成了**整片 MI-GAN ONNX 对照版**：438 帧逐帧定位，左上固定字样、右下固定字样及抖音标识出现的区域分别送入 MI-GAN ONNX；模型每次只修复一个 512×512 局部画面，合成时只覆盖遮挡区域。Mac CPU 离线处理约 302 秒，H.264 视频 14.6 秒、原 AAC 音轨 14.7 秒，整片可解码。测试片 `~/Movies/MaiChat/watermarks-removed-migan-onnx-test-2026-10-11.mp4` 已发送用户。它在左侧天空产生黄色细纹、在右上角留下零星亮点，肉眼画质不如临近干净帧补画版。因此这次**没有**把 MI-GAN 切成 App 默认去水印路径；真机性能也尚未测量。

用户随后指出临近帧补画版把手势削掉：第 58、266、429 帧对照原片确认，手和袖子伸入左侧补画矩形，固定矩形会误覆盖前景。修正版逐帧对照原帧与已补画背景，保留比背景明显更暗且从人物一侧伸入的前景；若白色标识和前景重叠，仅对该小处用 LaMa ONNX 修补。该样本共保护 40 帧前景，其中 9 帧调用 LaMa；第 266 帧袖口边的白色数字被修复。新片 `~/Movies/MaiChat/watermarks-removed-hand-preserved-2026-10-11.mp4` 保留 438 帧和原 AAC 音轨，已发用户检查。这个保护办法依赖样本的暗色衣袖与明亮天空对比，不能不经验证就当成通用人物分割器；移动端正式路径仍需独立实现和真机测试。

## iOS Agent 工具接入状态

用户认可“临近干净帧补画 + 前景保护 + 少量 LaMa 局部修复”样本后，iOS Agent 保留 `media_remove_watermark` 工具名，替换了内部处理器；旧 `delogo` Agent 实现已删除。工具不再暴露处理模式：有核实过的无遮挡参考帧时传 `before_s`、可选的 `after_s`，处理器逐帧插值、匹配颜色并羽化；没有干净参考帧时用本地 LaMa ONNX 补画。`foreground_edge` 保护从左/右进入的暗色前景，亮色字样与保护区重叠时才额外调用 ONNX。精确切换可用 `start_frame`/`end_frame`，避免按秒数截断时漏一帧。处理器用共享 C++/FFmpeg/OpenCV/ONNX Runtime，输出新 MP4 并直接复制原音轨；iOS 宿主打包模型并注册工具，桌面和 Android 暂未注册。

同一原片在 Mac 共享 C++ 路径完成端到端验证：438 帧、原 AAC 音轨，模型调用 44 次、前景保护 63 帧。新工具的参数校验及 MaiAgent 全套 43 项测试、桌面相关测试和 iOS 签名构建均通过；构建出的 App 已安装并启动于用户 iPhone。**仍未在 iPhone 上由 Agent 实际提交一次完整去水印任务**，所以耗时、内存、发热和手机端画质尚待真机实测。当前暗色前景判别是样本驱动的启发式规则；复杂背景、亮色衣服或人物遮住大面积文字时，不能保证同等效果。
