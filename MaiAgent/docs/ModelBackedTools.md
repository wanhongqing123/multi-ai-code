# 主控 Agent 与带模型工具

状态：产品方向已确认；本文区分目标设计与已交付功能。

## 角色

```text
用户 ──对话──> 主控 Agent
                │
                ├─普通工具：文件、FFmpeg、消息、端侧视觉
                │            输入精确参数，返回执行结果
                │
                └─特殊工具：视频创作工具
                             │  显式声明绑定模型、能力、约束和任务策略
                             │  接收高层意图、相关上下文与后续消息
                             └─绑定的视频模型：Seedance 2.0
```

特殊工具始终是注册表中的**工具**，不是泛型 `MaiSubAgent` 会话。它有稳定的名称和契约，
主控 Agent 能从工具说明与能力元数据知道它绑定什么模型、能做什么，以及何时委派。
`MaiSubAgent` 仍可用于其他独立会话任务，不是此处的必经层。

## 交流方式

主控的动作仍是工具调用，但给特殊工具的是自然语言消息和完整的相关任务上下文；
普通工具继续接收路径、坐标、滤镜参数等精确输入。特殊工具自己把高层需求转成模型所需参数，
管理任务状态，并把能力说明、澄清需求、进度或结果交回主控。主控是用户的唯一对话入口。

同一个特殊工具入口可以支持以下往返，不向主控暴露“创建视频任务”和“查询任务”两个底层工具：

```text
seedance_video(action="discover", message="你现在能做什么？")
  → 绑定模型、能力清单、当前可用状态与限制

seedance_video(action="delegate", message="按用户偏好制作小猫奔跑视频",
               context="相关历史、偏好、素材、完成标准")
  → conversation_id、任务状态、必要时的澄清问题

seedance_video(action="continue", conversation_id="...", message="进展如何？")
  → 进度或成品；后续要求仍走同一个工具入口
```

`action` 是工具协议中的交互意图，不是要求主控替视频模型选择底层 `duration`、`ratio` 等参数。
绑定模型不一定有独立的自由问答 API；工具可以依据已验证的能力元数据回答能力问题。
未验证的能力不得自报可用。模型如果只能输出视频，文字澄清和能力答复由工具的编排层完成。

## 能力元数据与任务状态

能力元数据至少含工具类型、绑定模型 ID 与版本、能力 ID、输入输出模态、可用状态、限制、
预计时延和计费信息。主控根据它路由任务；工具仍可用自然语言解释能力与限制。
当供应商能力、账户授权或模型版本变化时，工具更新能力状态，不能仅依赖模型自述。
能力状态分三层报告：`model_support`（模型理论能力）、`api_support`（接口开放情况）和
`tool_status`（当前工具真正能跑通的路径）。**主控只能把 `tool_status=available` 当作
可派单能力**；例如模型和 API 都支持视频编辑，但本地视频上传尚未接通时，不能把
`video_edit_from_local_file` 报成可用。

主控传入完整的**相关任务上下文**：用户意图、相关对话历史、偏好、素材、任务背景、约束
与完成标准。长历史可以摘要，但不能丢失影响结果的条件；无关内容不用原样传递。
媒体内容不塞进模型间对话：主控只传工作区文件路径、相关上下文和指令；共享工具层负责
读取、必要时转格式、上传、下载，再把新文件路径交回主控。图片模型与视频模型复用同一
文件交接原则。不同供应商的传输能力不相同：图片可直接由工具层编码提交时无需先上传；
视频若只接受 URL 或素材 ID，则需要工具层有真实可用的上传路径，不能把本地路径当成 URL。

AI 助手直接附带的图片在发送前已写入当前会话工作区，模型上下文会带该附件的
`part.id` 和精确 `workspace_path`。IM 聊天图片由 IM SDK 先下载到 App 缓存；
`maichat_get_messages` 与 `maichat_search_messages` 只处理本次返回的图片消息，
按消息 ID 建立 `im-image-<id>.<ext>` 工作区硬链接并返回精确路径。若文件系统
不允许硬链接，返回仍在 App 可访问范围内的本地绝对路径；原始图片字节不重编码。
会话列表只展示摘要，不为了列表页读取或复制其他会话的媒体。

AI 助手的消息引用保存被引用消息的 ID，并在本次模型请求中从同一会话的历史消息
解析原文与准确媒体路径。用户图片/视频片段和 `agent_send_media` 交付的图片、视频、音频
卡片都可被引用；模型拿到路径后可直接调用保存或处理工具。引用不复制媒体字节，
也不允许跨会话引用。引用图片只自动传路径，不额外塞入像素；需要看画面时再调用查看工具。

长任务保存已提交、运行中、需澄清、成功、失败、取消状态和持久化 ID。只有能测量时
才显示百分比，否则展示真实阶段与等待时长。
工具需区分“已提交”和“已完成”，保存产物路径，限制重试次数与成本，保留失败原因。
云端任务异步运行不等于主控同一轮可以并行工作；后台查询完成后直接把最终回复交给主模型。
确认失败时，核心先把原始原因交给主模型尝试修复或改用合适的工具，不抢先向用户展示
中间故障；主模型本身不可用时才显示兜底状态。鉴权拒绝等确定性的 4xx 错误停止
原查询链路；普通 429 和暂时性网络错误有界重试，明确的欠费错误与普通 429 分开处理。
供应商报告成功却没有可用产物时，也按失败提示，避免任务永久停留在“运行中”。

付费的 `delegate` / `revise` 每次都经过用户确认闸门，不能用会话级“以后都允许”
绕过。主控应先展示人物、服装、场景、动作和输出规格；视频新建任务未显式给出
时长、分辨率、画幅时，工具会拒绝提交并要求澄清。只读的 `discover`、`diagnose`
与 `continue` 不触发付费确认。`continue` 保留为手动排障入口；正常任务完成
应由协调器通知主模型，无需模型反复调用它。

## 面向多个专业模型的实现边界

主控是唯一与用户对话的角色，负责理解目标、拆分任务、选择专家、综合结果和交付。
一个专业助手是**注册在主控工具清单中的稳定能力**，绑定一个已配置的领域模型及其执行策略；
它可以有自己的任务状态，但不默认获得主控的完整对话、所有工具或用户权限。
`MaiSubAgent` 是另一种机制：它是可并行运行的普通 Agent 会话，适合上下文隔离，
不等同于绑定 Seedance、Seedream 等特定模型的专业助手。

```text
用户 ──需求／反馈──> 主控 Agent ──选择专家、传任务──> 专业助手工具注册表
                       ↑                              ├─ 视频专家 → Seedance 适配器
                       │                              ├─ 图片专家 → Seedream 适配器
                       └──── 状态／问题／产物引用 ────└─ 后续领域专家 → 对应适配器
                                      │
                           共享任务存储与工作区文件服务
```

每个专业助手采用同一套**内部契约**，供应商 API 留在适配器里：

| 阶段 | 主控发送／接收 | 专业助手负责 |
|---|---|---|
| 发现 | 能力 ID、输入输出模态、已验证状态、限制、费用提示 | 从配置和实际授权报告能力；不能让模型凭空自报 |
| 委派 | 用户目标、相关上下文、文件引用、约束和完成标准 | 检查能力、准备素材、提交任务，返回稳定任务 ID |
| 跟进 | 任务 ID 与新的用户要求 | 查询真实阶段；需要澄清时给出明确问题 |
| 完成 | 产物路径、媒体类型、可核实的结果摘要 | 下载、验证并保存产物；失败保留原因 |
| 取消 | 任务 ID | 停止本地等待；若供应商可取消，再明确报告云端取消结果 |

主控传的是**相关上下文**，不是把整个历史或媒体 Base64 塞给另一个模型。
文件引用使用工作区内的受控路径，读文件、上传和下载由共享服务完成。
专业助手接到任务后只能使用声明过的能力；若底层模型不提供自由问答接口，
`discover` 与澄清由适配器依据能力元数据和参数规则回答，不能伪装成模型亲自对话。

可扩展的核心应由三层构成：

1. **专业助手注册表**：为每个稳定工具名绑定模型 ID、能力和适配器工厂；主控只看到可派单能力。
   `MaiToolSpec` 目前只有名称、描述和 JSON Schema，需增加内部机器可读元数据，
   再把简短、真实的能力说明写进给主控的工具描述。
2. **任务协调器**：把 `queued/running/needs_input/succeeded/failed/cancelled`、供应商任务 ID、
   所属主会话、输出文件和错误持久化。提交立即返回；后台查询结束后交给主模型分析，
   主控在此期间可以处理别的事。当前轮询已移到 MaiAgent 后台工作线程。
3. **领域适配器**：Seedance、Seedream 和后续模型分别翻译请求、处理供应商鉴权与响应；
   通用的路径校验、网络传输、下载限额和任务存储只实现一次；取消接口仍需供应商支持。
   密钥由各端安全存储提供，主控的模型上下文与工具结果不得包含密钥。

按 `CodingStyle.md` 第 14 节，领域能力还要有不依赖模型工具 JSON 的类型化直接入口。
界面和后台任务调用这个入口，`MaiTool` 只解析参数、检查权限并把结果适配给主控；
不能让其他模块为了生成图片而伪造一次 `MaiTool::execute()` 请求。

先让现有两个工具共用任务与能力契约，再接入第三个模型验证接口是否足够通用；
不要预先把某一家供应商的 `duration`、`ratio` 或图像尺寸塞进通用接口。
静态图生成通常是一次请求，视频生成通常是异步任务，未来的聊天型领域模型可能需要
多轮对话。统一的是**委派、任务状态与结果交接**，不是强迫所有模型使用同一种底层 API。

## 目标接口：专家是工具，执行是任务

### 编辑反馈与专家上下文

首次 `delegate` 的 `context` 仍由主控筛选并传入，工具不会自动读取完整聊天历史。
现在共享存储会为成功提交的 Seedance 任务和成功生成的 Seedream 图片建立
`spt_` 任务记录，保存所属 AI 会话、原始目标、上下文摘要、素材引用和上一版任务 ID。
Seedance 新任务返回的 `conversation_id` 是本地 `spt_` ID，同时保留供应商 `task_id`；
旧对话里的供应商任务 ID 仍可用于 `continue` 查状态。`continue` 不接收修改意见。
新 `revise` 调用按同一 AI 会话读取上一版记录：视频用之前的供应商任务作为输入，
图片用上一版生成文件作为输入，并把之前目标与本次反馈交给模型。
这是一条有界的**任务修订记忆**，不是专业模型自动继承了全部用户聊天记录。

任务身份和原始目标不可变；运行状态、最终文字、最后错误和已验证的本地产物路径
现已保存在同一条任务记录里。主控只给专家传与本次修订相关的摘要，
而不是把整个用户聊天记录复制过去。

```text
第一轮：主控委派“把视频背景换成海边” → 专家任务 A → 产物 A.mp4
用户反馈：“人物边缘有白边”
第二轮：主控创建修订任务 B
        parentTaskId=A，素材=A.mp4，反馈=“只修人物边缘白边”
        专家读取 A 的目标和约束 → 生成 B.mp4 → 主控验收并交付
```

`continue` 只表示查状态；`revise` 负责接收反馈、继承经过筛选的历史约束，
并在提交付费请求前明确选用哪一个旧产物。它不能偷偷把反馈写进已运行的云端任务。
对话型专家可以在自己的任务链里保留多轮对话；Seedance / Seedream 这种生成接口
没有通用对话记忆时，由协调器保存任务链、由适配器构造下一次请求。

## 当前的完成交接

每个专家有独立工具名，能力和参数由自己的适配器提供。提交生成任务后，工具立即返回
本地任务 ID，主模型可以结束这一轮；后台按供应商任务 ID 查询，不重新提交付费任务。
任务成功、失败或需要澄清时，最终回复和可选产物路径更新在任务记录中。主会话空闲后，
共享核心把该回复作为临时观察交给主模型，由主模型分析并回复用户。

流式片段只在子任务中累计，不逐片触发主模型。纯文字结果没有产物文件也能完成；
视频生成任务必须先确认本地文件存在且非空。通知只保留固定的主模型消息 ID 和完成标记，
App 重启后可以续查任务并避免重复生成用户气泡。详见
[专业模型完成后交回主模型](SpecialistCompletionSessions.md)。

## 状态、恢复和费用边界

以下是后续扩展目标；当前实现只记录 submitted、running、needs_input、succeeded、failed、
canceled，不支持供应商取消、自动付费重试或百分比进度。

```text
queued → submitting → running → succeeded
             │          ├──────→ needs_input → running
             │          ├──────→ failed / expired
             └──────────→ submission_unknown
任何未结束状态 ─→ cancel_requested ─→ cancelled 或 provider_still_running
```

`submission_unknown` 表示网络断在“请求可能已到供应商，但本地没拿到任务 ID”之间；
不能盲目重试付费生成。只有供应商明确支持幂等键或查回原任务时才能自动恢复提交。
任务记录已保存供应商 ID、提交时间、最近阶段、最后错误和本地产物引用；重试次数
仍属后续扩展。
重启时：有供应商 ID 的任务继续查询；没有 ID 且提交结果不确定的任务如实标为
`submission_unknown`；已完成任务只校验本地文件存在，不重新生成。

`cancel_requested` 不是 `cancelled`：本地停止等待不等于云端任务已经取消或不会计费。
自动重试和自动质检都必须有次数、时长和费用上限；未设预算前只做可证明不会重复付费的重试。
同一任务的晚到回调要靠状态版本号或比较更新拒绝，避免完成后又被旧的 `running` 覆盖。

## 对照现有代码的改造顺序

1. **抽类型化服务与共享传输**：把 `MaiArkMediaTools.cpp` 里的供应商调用从
   `MaiTool::execute()` 分离；让界面、后台任务和工具壳调用同一服务。当前 Ark 下载是
   通过构造 `curl_download` 工具及 JSON 参数来复用实现，下一步应把下载逻辑抽成
   可直接调用的文件服务，再让两个工具壳使用它，满足 `CodingStyle.md` 第 14 节。
2. **做能力登记**：内部元数据记录模型绑定、模态、配置状态和端到端验证状态；
   根据配置生成简短工具描述。只有当前设备与账号真实可用的路径标为 `available`。
   `MaiToolSpec` 的线格式目前只有名称、描述和 Schema，不要把供应商元数据原样塞进
   OpenAI 的函数声明；主控可通过描述和 `discover` 得到经过筛选的能力。
3. **任务存储与后台交接已落地**：独立任务表保存状态和回复；按供应商 ID 查询后，
   主会话空闲时让主模型分析一次结果。流式过程不产生通用事件日志。
4. **迁移现有专家**：Seedance 先迁异步视频流程，Seedream 再迁单次图片生成；
   保持 `seedance_video` / `seedream_image` 名称兼容旧对话。用第三个不同形态的模型
   验证接口扩展性，再考虑自主规划或多轮澄清。

现阶段不要把 `MaiSubAgent` 的完整工具集直接交给专业模型。它与专业助手的任务
所有权、模型绑定和能力限制不同；若将来某个专家确实需要自己的规划模型，
也应由该专家的适配器显式配置它能调用的共享服务，而不是继承主控的全部权限。

## 当前落地与后续

iOS 已验证 Seedance 文生视频的云端生成、下载与会话媒体交付。当前
`seedance_video` 和 `seedream_image` 的请求、校验、任务状态及下载实现已迁入
`MaiAgent/AgentTools/MaiArkMediaTools.cpp`；iOS 从 Keychain 提供方舟 Key，Android 从
Keystore 提供，桌面端从 `MAICHAT_ARK_API_KEY` 环境变量提供。各端注册同一套工具，
新迁移后的云端请求仍需逐端实测，不能把编译通过当成端到端验收。
2026-10-04 已在 Mac 上用共享 C++ 工具和真实方舟 Key 验证多参考图与首尾帧：
Seedream 输出 1024×1024 PNG（1,208,054 字节）；Seedance 任务从 `running` 到
`succeeded`，输出 4.041667 秒 H.264 MP4（864×496，97 帧，660,085 字节），
FFmpeg 全片解码通过，首尾画面与输入素材对应。测试用的是无人物的抽象图形；
产物位于 `MaiAgent/build/ark-validation/`。这证明共享核心在 Mac 上的两条路径，
不代表 iOS、Android 和 Windows 已做真实云端验收。
随后又用同一批无人物素材真实验证修订：Seedream `revise` 用上一版 PNG 和新反馈
生成新的 1024×1024 PNG；Seedance `revise` 用上一版供应商视频任务和新反馈创建
新的任务，成功生成 4.041667 秒 H.264 MP4（864×496，97 帧，925,964 字节），
FFmpeg 全片解码通过。两个结果都带 `revision_of` 指向旧任务；图片像素与上一版有差异。
这些是 Mac 共享核心的验收，移动端宿主取密钥和 UI 交互仍需真机验证。
最初暴露的
`seedance_create_video`、`seedance_get_video` 已从主控工具清单撤下，只保留
`seedance_video` 特殊工具入口；任务提交与查询留在工具内部。
图片创作使用单一 `seedream_image` 入口，绑定 Seedream 5.0 flash：文生图时提交提示词，
编辑时主控只传已有图片的工作区路径与指令，由工具层读取图片、编码提交并将新 PNG 保存回工作区。
图片接口支持 Base64 输入，因此这条本地图片交接路径不依赖视频所需的 TOS 上传通道。
Seedance 2.0 模型和视频生成接口支持视频参考、编辑与延长。当前工具已接入
HTTPS 视频 URL 或已完成 Seedance 任务的引用路径；编辑请求已在方舟服务端验证出片，
iOS 工具层仍需单独验收。任意本地 `video_path` 的上传尚未接通，因此 discover 必须
将其报告为 `upload_not_configured`，不能和已验证的文生视频混作一个“可用”状态。
方舟视频生成接口要求视频 URL 或素材 ID；长效存储的 AK/SK 不应下发到手机，
本地上传应接服务端签发的短时上传／读取链接或等价的受控存储通道。
接口取值参考[方舟创建视频生成任务文档](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)。

对无需指定真人身份的写实人物视频，工具支持 `virtual_avatar_asset_id`：从方舟
体验中心的预置虚拟人像库选取素材 ID，在请求中以 `asset://<ID>`、
`image_url` 与 `reference_image` 角色提交。可选 `reference_image_path` 作为第二张
非真人脸参考图片；提示词按“图片 1 / 图片 2”指代素材。此路径不支持用用户真人照片
自动替换成虚拟人像。对已在方舟同账号通过真人认证、授权且状态可用的人像素材，
使用独立的 `authorized_portrait_asset_id` 输入，同样通过 `asset://<ID>` 引用，
不上传本地真人人脸图片。两项 Asset ID 互斥，均须先在方舟体验中心取得。
预置素材须由账号先在体验中心开通并取得 Asset ID，
当前工具不持有素材管理 API 所需的 AK/SK，也不自动检索头像库。
参考[方舟含肖像视频指南](https://docs.volcengine.com/docs/ark/seedance-portrait-asset-guide?lang=zh)。
方舟已公开真人人像素材资产 API，但当前 `seedance_video` 未接入录入链路。
公开流程是 `CreateVisualValidateSession` 让本人完成 H5 真人认证，
`GetVisualValidateResult` 取得对应的 Asset Group ID；之后把同一人物的图片放到
可访问的 HTTPS 地址，调用 `CreateAsset`，通过 `GetAsset` 等待 `Active`，最后才使用
`asset://<Asset ID>`。接口要求 AK/SK，和现有的视频推理 API Key 不同；素材入库时
还会做人脸一致性校验，多人脸图片不能入库。高级创作权益 Entry 可免费开通 Assets API，
但需满足企业认证及平台开通条件。现有客户端缺少 AK/SK 服务端、认证回调和安全的图片暂存；
仅凭一张本地真人照片无法在后台无感完成该授权流程。
详见[真人人像素材资产使用指南](https://docs.volcengine.com/docs/ark/guide-preview?lang=zh)和
[高级创作权益说明](https://docs.volcengine.com/docs/ark/seedance-2-0-purchase-guide?lang=zh)。

当前给主控模型的 `MaiToolSpec` 仍只有名称、描述和 JSON Schema；内部能力快照尚未
接入自动任务路由。当前视频工具已具备后台状态查询和完成转交，尚无完整的内部对话规划和自动质检。

共享核心现已提供 `MaiSpecialistInfo` / `MaiSpecialistCapability` 机器可读快照，
`MaiToolRegistry::specialists()` 可按当前密钥配置查询专家绑定模型与能力状态；
`discover` 与注册表从同一份元数据生成，避免两份能力清单漂移。
方舟[图片生成 API 文档](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh)
列出 Seedream 5.0 flash 的多参考图、交互编辑和图层拆分能力。当前工具接通了
2–10 张工作区图片输入并生成单张 PNG，Mac 共享核心已做真实云端验证；
移动端仍需独立验收，因此设备侧状态保持 `implemented_unverified`。
图层拆分仍为 `not_implemented`，连续组图输出是该模型不支持。
方舟[视频任务 API 文档](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)
列出 Seedance 2.0 的首尾帧与多模态参考能力；模型支持不等于工具已验收，
不能仅因模型支持就向主控报告为可用。
其中首尾帧输入现已接通 `image_path` + `last_frame_path` 两张工作区图片，
并补上文档允许的 `21:9` 与 `4k` 参数；Mac 共享核心已用真实视频任务验证，
移动端尚未实测，设备侧仍报告为 `implemented_unverified`。
除虚拟人像加一张本地对象参考图外，多参考图／视频／音频仍是能力缺口，不能报告为已实现。

1. 为视频 URL／已完成的 Seedance 任务接通编辑、延长和参考生视频；本地视频上传独立验收。
2. 在共享工具接口加入机器可读的模型绑定与能力元数据，并核对实际授权与服务状态。
3. 长任务已具备持久化状态、后台查询和重启恢复；真实百分比进度仍需供应商支持。
4. 加入有界的澄清、创意规划与质检重试；明确费用和停止条件。
5. 其他模型服务复用同一特殊工具契约，逐步扩展到其他平台。

### 智谱 GLM 图片与视频

共享实现位于 `MaiAgent/AgentTools/MaiGlmMediaTools.cpp`，工具名 `glm_video` 和
`glm_image`。移动端仅在主模型使用 `open.bigmodel.cn` 时从同一份 GLM 5.3
密钥配置读取；桌面端复用相同供应商的模型配置密钥。密钥不进入工具参数、能力清单或
持久化任务记录。两项工具的付费 `delegate` 都需逐次确认，提交后由既有协调器查询
异步任务、下载产物并通知主模型，`continue` 仅供排障。

`glm_video` 绑定 `cogvideox-3`，支持文生视频、本地 PNG/JPEG 单图生视频和首尾帧
生视频；已有视频编辑不在此接口能力内。`glm_image` 绑定 `glm-image`，只支持异步
文生图；已有图片编辑不在此接口能力内。能力状态在云端与移动端实测前均为
`implemented_unverified`。密钥来自 GLM 5.3 配置不代表 Coding Plan 套餐自动拥有
开放平台的图像／视频模型权限，供应商若拒绝会返回结构化错误，不能宣称生成成功。
接口参考[视频生成异步 API](https://docs.bigmodel.cn/api-reference/%E6%A8%A1%E5%9E%8B-api/%E8%A7%86%E9%A2%91%E7%94%9F%E6%88%90%E5%BC%82%E6%AD%A5)、
[图片生成异步 API](https://docs.bigmodel.cn/api-reference/%E6%A8%A1%E5%9E%8B-api/%E5%9B%BE%E5%83%8F%E7%94%9F%E6%88%90%E5%BC%82%E6%AD%A5)及
[查询异步结果](https://docs.bigmodel.cn/api-reference/%E6%A8%A1%E5%9E%8B-api/%E6%9F%A5%E8%AF%A2%E5%BC%82%E6%AD%A5%E7%BB%93%E6%9E%9C)。

### 万相 2.7 视频编辑

`wan_video_edit` 是独立于 Seedance 的专业工具，绑定 `wan2.7-videoedit`，沿用
`discover` → `delegate` → `continue` → `revise` 的任务契约。主控传工作区视频路径、
编辑目标及可选的参考图路径；工具上传素材、提交异步编辑任务、查询状态并把 MP4 保存回
工作区。修订只接受同一 AI 会话中已完成的上一版任务。能力元数据按实际配置返回，
不会把万相 3.0 的实测结果算作 2.7 的验收。

模型仅接受 2–10 秒 MP4/MOV，最多 4 张参考图，输出 720P 或 1080P。默认保留原声，
不截断视频；超长素材应由主控先明确分段，再决定是否拼接。iOS 的 API Key 存在
Keychain、Workspace ID 存在本机设置；Android 的 Key 存在 Keystore；Desktop 从
`MAICHAT_WAN_API_KEY` 与 `MAICHAT_WAN_WORKSPACE_ID` 读取。密钥不进入仓库。

当前本地上传使用百炼的私有临时存储，按官方说明**仅供开发与测试**，URL 48 小时后
失效；生产部署要换成长期可用的 OSS 受控上传通道。生成结果链接仅保留 24 小时，
`continue` 在任务完成时立即下载。
2026-10-04 Mac 共享核心真实验证：用 7.593 秒成人公开样本，`delegate` 上传并提交
`wan2.7-videoedit`，`continue` 下载 7.57 秒 H.264/AAC MP4（1280×720、227 帧、
4,653,511 字节），FFmpeg 全片解码通过；对照帧确认黑 T 恤变为蓝色牛仔外套。
MaiAgent 的 31 项 CTest 通过，iOS 无签名构建通过。iOS 真机云端调用、Android 和
Desktop 尚未验证；不能把上述 Mac 验收扩展成各端都已可用。
接口：[视频编辑 API](https://help.aliyun.com/zh/model-studio/wan-video-editing-api-reference)、
[临时文件上传](https://help.aliyun.com/zh/model-studio/get-temporary-file-url)。

同一百炼配置现在还供两个独立工具使用：

- `wan_video` 绑定 `wan3.0-video`，接通文生视频、首帧/首尾帧、本地单段视频参考编辑和
  延长、最多十张本地参考图；多段参考视频、音频、文档和网页输入仍未接通，不能报告可用。
  提交后以 `continue` 查询并保存 MP4；`revise` 仅继承同一 AI 会话的已完成任务。
- `qwen_image` 绑定 `qwen-image-3.0-pro`，文生图或最多三张本地图片编辑后保存新 PNG。
  模型接口是同步生成，工具不提供虚构的轮询进度；`revise` 读取本会话上一版 PNG。

两者的真实 Mac 共享核心验证（2026-10-04）：Wan3.0 用成人公开视频的 7.59 秒输入
生成 5 秒、854×480、150 帧 H.264 MP4（2,282,521 字节），FFmpeg 全片解码通过，
对照帧可见黑 T 恤换成牛仔外套；Qwen 用合成图编辑生成 1024×1024 RGB PNG，画面为
淡蓝背景上的黄色纸飞机，并用纯文字生成了奶油色背景上的绿色折纸船 PNG。
它们不是 iOS/Android 真机的云端验收；设备侧能力仍按
`implemented_unverified` 上报。接口：[Wan3.0 视频生成](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference)、
[Qwen-Image-3.0-Pro](https://help.aliyun.com/zh/model-studio/qwen-image-generation-and-editing-api-reference)。

当前工具选择仍由主模型完成：`MaiTurnRunner::buildRequest` 把注册表中的工具名称、描述和
参数格式随每次模型请求送出，主模型自行调用 `discover` 和 `delegate`。
模型工具失败后的任务接续原则见 [SpecialistFailureRecovery.md](SpecialistFailureRecovery.md)。
`MaiToolRegistry::specialists()` 目前只有内部/测试调用，没有自动路由或供应商默认优先级。
因此“生成一个视频”同时匹配 Seedance 与 Wan3.0，不能声称一定选中某个服务；用户明确
点名模型时应遵从。编辑已有短视频应优先考虑 `wan_video_edit`，含更多参考素材或更长
生成时可考虑 `wan_video`，但这些只是工具描述给主模型的能力线索，不是已实现的硬路由。

排查百炼授权时三个工具提供无生成费用的 `action="diagnose"`：用当前设备保存的 Key 和
Workspace ID 查询该模型在限额列表里是否可见，并返回请求频率/用量上限；不回传 Key，
也**不代表**已核对免费余额或每一类生成请求的权限。供应商拒绝时工具保留 HTTP 状态、
`provider_code` 和 `request_id`，方便将手机端与 Mac 端请求对照。Mac 使用此前提供的
CSV 凭据对三个模型运行此诊断均返回 `model_visible=true`；iPhone 端需独立验证。
