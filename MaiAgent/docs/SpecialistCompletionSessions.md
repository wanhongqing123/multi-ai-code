# 专业模型完成后交回主模型

主模型调用 `delegate`／`revise` 后，专业工具在所属 AI 会话中保存一条 `spt_` 任务：
原始目标、供应商任务 ID、素材引用和修订关系。它是任务记录，不伪装成供应商提供的聊天 API。

工作流只有一条：

```text
主模型派任务 → 专业模型执行 → 子任务保存最终回复 → 主模型收到回复并分析 → 回复用户
```

运行中的流式文字暂存于子任务的 `partialText`，不逐片触发主模型推理。任务完成、失败或
需要澄清时，将最终文字、状态和可选文件路径写入同一条任务记录。主模型收到的是这一次
子模型的最终回复；纯文字任务没有图片／视频路径也能完成。视频生成任务则必须先拿到非空、
可读取的媒体文件，才能上报成功。

App 运行期间，后台工作线程按已保存的供应商任务 ID 查询状态；重启后从未完成任务继续查，
不会重新提交付费生成。查到终态后，等主会话空闲，把子模型回复作为一次**仅供模型读取的
临时观察**交给主模型，不插入假的用户消息。主模型可以检查文件和结果，然后写出用户可见
的回复。这样用户无需再问“完成了吗”。

任务行只保存一个 `notificationMessageId` 与 `notifiedAt`。主模型回复前先固定消息 ID；
若 App 在回复写入后、标记通知完成前退出，重启时沿用同一条消息 ID 重新分析，
不会增加第二个气泡；不能把被中断的半截文字误判成完成。
供应商短暂网络故障会稍后重查；供应商明确报任务失败时，把失败原因交给主模型解释。

iOS 后台可能暂停或终止 App，这套机制不声称能无限保活。App 恢复运行时，会从本地任务
记录继续查询和转交结果。当前只对已接入 `continue` 的异步专业工具自动查询；同步图片
工具在调用当轮就把产物回灌给主模型，不再额外通知一次。
