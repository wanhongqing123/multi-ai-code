# 主模型与模型工具的失败接续

用户交给主模型的是一件事，不是某个供应商的一次调用。一次调用失败只结束这次尝试；
主模型保留原始目标、素材引用和已确认的参数，先寻找可行的修复或替代路径，完成后再交付。
成功交付后可以简短说明中间换过哪家模型。不能把一家模型的欠费、超时或审核错误
直接当作面向用户的最终答复。

## 交接与责任

模型工具负责保留供应商的原始错误、调用阶段、请求 ID、供应商任务 ID、输入文件引用
和已经下载的产物路径。工具可以自行修正明确且不改变用户意图的协议或传输问题；
不能猜测笼统审核错误究竟由文字还是图片引起，也不能把一次查询失败说成生成失败。

主模型收到工具结果后判断下一步。它能读取已注册模型工具的 `discover` 能力，
比较用户要求、素材类型和各工具实际接通的能力，再继续调用适合的工具。
每次新的付费提交仍经过原有的逐次确认；查询已提交任务的状态不产生新的提交。
用户点名了特定供应商时，不能悄悄换成另一家并冒充原供应商的结果。

| 观察到的情况 | 主模型应做的事 | 不应做的事 |
|---|---|---|
| 提交前欠费、密钥缺失、无权限 | 保留原请求与素材，检查其他已配置、能力匹配的模型工具，继续完成任务 | 让用户先充值，或重复调用同一家 |
| 已获得任务 ID，随后状态查询出错 | 保留任务 ID；优先恢复查询。若仍无法确认，明确区分“结果未知”和“生成失败” | 静默再次提交同一付费任务 |
| 频率限制、暂时性网络故障 | 有界重试查询，必要时选择等效工具 | 无上限重试或反复创建任务 |
| 明确的参数或传输错误 | 仅修复被指出的字段，再按付费确认流程继续 | 改写人物、场景或用户原意 |
| 文本、图片或笼统内容审核错误 | 检查实际提交的文字与素材；按证据逐项调整。保留原图与改变记录，必要时选用允许该输入的工具 | 把笼统错误武断归因于图片，或伪装明令禁止的输入 |
| 供应商明确返回任务失败 | 保留原因与任务 ID，判断是否能修复后重试或换路径 | 当成仍在生成，或声称已有产物 |
| 云端已完成但下载失败 | 先用原任务 ID 恢复下载并核对文件 | 为拿同一产物重新付费生成 |
| 原因未知 | 读原始代码、消息与所处阶段；尝试成本可控且有依据的修复或能力匹配的替代工具 | 猜测原因、盲目付费探针或马上宣布失败 |

交付必须以真实的输出文件为依据。对于媒体任务，主模型拿到有效路径后通过
`agent_send_media` 交付；没有文件时不能说已经出片。只有确实没有可行路径，或者
用户拒绝了必要的付费确认，才简洁说明尚未完成和需要用户决定的事。

## 当前代码落点

- `MaiTurnRunner.cpp` 把同步模型工具的供应商错误连同恢复方向回灌给主模型；
  异步子任务的回复也带原始目标、素材引用、状态和错误。未知错误仍交给主模型分析。
- `MaiAgent.cpp` 后台持久化异步任务和供应商任务 ID，查询结束后唤醒主模型。
  主模型可工作时，不先向用户展示子任务失败卡片；主模型本身失败才显示兜底信息。
- 欠费与普通 `429` 限流分开识别。欠费不会被当作限流重复查询三次；
  但已提交任务查询时遇到欠费，记录的是**查询不可用、生成结果未知**。
- MiniMax 对这种查询失败的任务允许沿原供应商任务 ID 再查，不强制重建付费任务。
- `MaiMobileAgent.cpp` 与桌面 `AgentController.cpp` 的主模型指令要求先继续解决任务，
  交付后再按需说明供应商切换；付费确认仍由权限闸门执行。

这套机制让主模型有机会接手，但当前没有一个替主模型硬编码供应商优先级的路由器，
也不能保证任意未知错误都能自动解决。离线测试覆盖欠费后调用另一工具、异步欠费
回灌、普通限流与欠费分离，以及主模型不可用时的兜底；供应商真实效果需要在明确
授权的付费验收中验证。App 被系统终止后的后台运行时长仍受操作系统限制，
持久化任务可在再次运行时继续查询，但这不等于 iOS 无限后台保活。
