### 当前明确的后续项

- Desktop 图片预览仍保留可缩放独立窗口；与 iOS 的全屏手势和连续浏览结构尚未完全一致。
- Windows 缺少本轮 Qt 源码的实际构建、安装版操作和视频画面核查；Mac 测试不能代替 Windows 结果。
- Android 目前只有模拟器验收，实体机上的媒体、横竖屏、语音和账号切换仍需用实际安装版检查。

按 2026-09-23 确认的顺序执行：① Android 交互逻辑与后台迁移；② Android 字体排版；③ iOS AI 助手；④ Android AI 助手。每项验证、提交后再进入下一项。

## 1. Android 交互逻辑与后台迁移

已完成代码与自动化验证：117 项单元测试、6 项 Android 模拟器测试通过。包括历史位置保持、输入框复用、键盘展开定位、本地发送定位、右滑取消与返回、原生 AAC 录音、UI 心跳，以及真实腾讯云实时转写的中途结果与服务端最终结果。

| 范围 | 实现 |
| --- | --- |
| 聊天页 | 复用输入框与原生 ListView 消息行；状态和回执不重建整个页面；草稿按账号与好友隔离 |
| 历史 | 后台读取最近 20 条，向前分页 20 条；离开会话后只保留近期缓存，数据库保留完整历史 |
| 定位 | 进入页面、用户展开键盘、自己发送三类意图；自己发送按消息 ID 定位；其他数据更新保留可见消息及偏移 |
| 布局时机 | ListView 消费数据同步后，在绘制前应用定位；长消息按实际行高对齐底部，无延时补滚动 |
| 键盘 | 页面负责系统 Insets，输入区和消息区共同跟随键盘动画；预览或后台恢复不新增定位意图 |
| 返回 | 全页面右滑，区分水平返回与纵向历史滚动；支持取消；Android 11+ 协同控制 IME，旧系统在开始返回时收起键盘 |
| 活动状态 | 接入与 iOS / Desktop 相同的在线自定义消息；人工三点、机器阶段耗时与任务总耗时；过期、乱序、正文替换；不写历史与未读 |
| 语音 | AAC 录制、停止和释放在音频线程；实时转写边说边显示，松手立即关闭录音预览；结果按原账号与好友发送 |
| 语音回退 | 实时服务失败保留录音；一句话识别与语音消息回退在原有路径继续处理 |
| 附件 | 复制、元数据、视频封面、预览文件读取都在后台；支持选择、发送和转发视频；补齐附件引用元数据 |
| 下载更新 | 封面与视频完成分别更新原消息，不新增消息、未读或定位意图 |

| 诊断 | 后台记录卡顿时的主线程栈、帧耗时和内存采样；滚动日志限容；导出也在后台 |

临时气泡使用列表底部预留的回复区域；显示、隐藏时交换等高区域，避免为了显示状态去滚动历史。

### 线程边界

| 线程 / 队列 | 工作 |
| --- | --- |
| UI 线程 | 用户事件、轻量展示状态发布、控件设置、布局绘制、焦点与系统键盘协调 |
| 历史队列 | 账号恢复、SQLite 读写、分页、去重、引用原消息读取、账号配置落盘 |
| IM 队列 | 腾讯 SDK 调用、消息元素拆分、自定义协议与元数据解析 |
| Markdown 队列 | Markdown 解析与准备；缓存未命中不退回主线程解析 |
| 媒体队列 / 图片队列 | 文件读取复制、图片降采样、视频元数据和封面、文本附件读取 |
| 音频 / 播放队列 | MediaRecorder、MediaPlayer 的配置、准备、停止与释放 |
| ASR 网络队列 | 签名、AAC 分帧、限速上传、JSON 结果合并、超时与清理 |
| 诊断队列 | 帧统计、主线程卡顿采样、内存采样、日志写入与导出 |

布局与绘制本身必须在 UI 线程；这里移走的是应用层 I/O、解析、音频和网络处理，不把后台工作再同步等待回主线程。异步回调校验账号、会话或请求代次；旧录音、旧附件和旧历史请求不能污染新会话。

### 构建环境

仓库使用 Gradle 7.5.1 / AGP 7.4.2。本机原有 GraalVM 17 的 `jlink` 缺少 `jdk.internal.vm.ci`，在修改前就无法生成 Android JDK image。验证使用独立 Temurin JDK 17，未替换系统默认 Java。

联调凭据仅写入已被 Git 忽略的本机配置；包含开发凭据的联调 APK 不作为公共发布资产。

### 协议依据

- 临时活动沿用 [交互设计](交互设计.md) 第 10 节。
- 实时语音采用[腾讯云 WebSocket ASR 协议](https://cloud.tencent.com/document/product/1093/48982)：与 iOS 同一 `16k_zh` 引擎；AAC 直接用于流式上传和录音回退，避免重复占用麦克风。识别参数与音频分帧在后台处理。已有文字的结束等待采用与 iOS 相同的一秒兜底，界面不等待这个阶段才退出录音状态。
- Markdown 表格使用 [Markwon 的 GFM 扩展](https://noties.io/Markwon/docs/v4/ext-tables/)。消息仍使用原生文本组件，不引入 WebView 消息列表。

## 2. Android 字体排版

已完成。按 iOS 视图内部实际生效值对齐：正文与列表 14、行距 4；标题 22 / 18 / 16 / 14；行内代码 13、代码块 12；时间 11 半粗蓝色。采用 Android 系统无衬线与等宽字体，保留系统字体缩放。

消息内去掉头像与昵称，正文后追加时间；突出 imcli 来源；来信使用清爽背景，发信用淡蓝气泡。Markdown 小圆点统一为蓝色实心点。已通过当前 117 项单元测试和聊天界面模拟器回归，并检查了实际截图。

## 3. iOS AI 助手

已完成。使用共用 `MaiMobileAgent` C ABI 接入 MaiAgent，支持持久会话、流式 Markdown、思考与工具详情、停止、审批与提问、模型和权限配置、图片/文本输入、语音转文字以及历史恢复。API Key 存在 Keychain；图片复制到稳定沙箱后以 Base64 Data URL 交给视觉模型。

## 4. Android AI 助手

已完成并补齐移动端功能。Android 通过 JNI 使用同一 `MaiMobileAgent`，支持持久会话、流式 Markdown、思考与工具详情、停止、审批与提问、Android Keystore 加密密钥、图片/文本输入、相册与拍照、语音转文字、历史图片恢复，以及 `glm-5.3` / `glm-5.3-flash` 快速切换。

AI 文件位于应用私有工作区；界面只保存相对路径，读取、图片探测与转换在后台线程完成。图片通过 Chat Completions `image_url` Data URL 发送，本地路径不交给模型。短会话从列表顶部开始，长会话进入、自己发送或活动状态出现时定位最新；用户浏览历史后不强制跳动。机器活动阶段耗时与任务总耗时使用与 iOS/Desktop 一致的秒/分秒格式。
