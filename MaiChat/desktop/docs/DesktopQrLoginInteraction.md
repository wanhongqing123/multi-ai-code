# 桌面端扫码登录交互

启动后显示居中的登录窗。若系统安全存储中有刷新令牌，先显示“正在恢复登录”，
续期并领取服务端 IM 凭据；成功则直接进入主界面。令牌已撤销或过期时清除本地
记录并生成二维码。网络暂时失败时保留可恢复的令牌，显示“恢复登录失败”与
“重试恢复登录”，不强迫用户重新扫码。

首次登录显示“正在生成登录二维码”。服务端 PNG、六位“核对码”和 120 秒倒计时
出现在同一面板。二维码只含 `maichat://auth/desktop?request_id=...`；随机
verifier 仅留在桌面进程内存。等待时提示用已登录手机扫码并核对数字。
手机读取扫码请求后，服务端将状态更新为 `scanned`；桌面轮询收到该状态时才
显示“已扫码，请在手机上确认”，不能只凭二维码被显示就推断已扫码。

手机批准后隐藏已兑换二维码，显示“登录成功，正在连接”，领取并校验 IM 凭据，
账号一致才进入主界面。明确拒绝显示“手机拒绝了这次登录”；批准手机的会话
失效则显示“手机授权已失效”。过期后隐藏旧码并提供新码。网络失败时仍保留
未过期二维码和倒计时，允许重试。窗口无手输账号入口，也不弹键盘。

更换二维码或关闭窗口时，用原 request_id/verifier 异步取消旧请求。若 claim
正在处理，先等待它完成；迟到的 claim200 会单独撤销签发的桌面会话，之后
才展示新码或结束窗口。手机已批准、桌面已采纳会话后，取消登录改为清除本地
安全存储并调用 `/auth/logout`，不会再取消那次二维码请求。

主界面“设置”提供“退出登录 / 切换账号”。确认后先停止远程桌面并登出 IM SDK，
再撤销账号服务会话并清除安全存储，随后退出应用；下次启动显示扫码登录。
刷新令牌仅存于 macOS Keychain 或 Windows Credential Manager，访问令牌和
服务端签发的 IM UserSig 只在进程内。远程桌面使用与 IM 同一账号的 UserSig。
