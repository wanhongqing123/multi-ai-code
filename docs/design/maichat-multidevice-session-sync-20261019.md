# MaiChat 多端 Session 同步方案（2026-10-19）

## 已确认的产品行为

- 同一 MaiChat 账号登录 Mac、Windows、iOS、Android 后，各端能看到其他设备创建的创作中心 Session。
- Session 固定由创建它的设备执行。本机工作目录、文件、工具和模型请求留在所属设备；手机不会接管 Mac 的编译任务。
- 其他设备能查看所属设备同步的可见对话和工具状态，并在所属设备在线时发送消息、停止、回答问题及处理权限请求。
- 控制端断线不停止所属设备正在执行的任务。重连后补齐遗漏记录；所属设备离线时仅显示目录及控制端已缓存的内容，输入保留为草稿，不自动排队执行。
- 不依赖腾讯 IM/TRTC 通道，不使用 OSS，不复制各端的 SQLite 数据库，不增加额外的设备间端到端加密。公网连接仍使用 TLS，所有访问按 MaiChat 账号鉴权。

## 服务边界

在现有阿里云 ECS 上独立运行 Session 同步服务。它只管理设备在线状态、Session 目录与同账号设备之间的消息路由；账号身份由已有账号服务核验，不建立第二套账号。所属设备直接调用模型供应商，服务不持有模型密钥，也不调用或代理供应商接口。

该服务会转送设备之间的可见会话文字和按需文件字节，但不长期保存完整历史或文件。这个设备通信边界与模型代理不同；实现前后均应在部署说明中明确记录。客户端各自缓存已收到的远端历史，完整可执行记录以所属设备本地库为准。

## 标识和路由

- 一个远端 Session 用「MaiChat 账号 ID、所属设备登录名额、所属设备安装实例、MaiAgent Session ID」定位。腾讯 IM ID 不参与。
- 账号服务已有 `ios_phone`、`android_phone`、`tablet`、`mac`、`windows` 登录名额。同步服务还需为每次设备连接分配代次；旧登录被替换后，旧代次的操作不能落到新设备。
- 客户端只发起到阿里云的 HTTPS 长轮询和上报，所属设备无需暴露公网端口。
  当前各端已有 HTTP 栈，先避免增加四端各异的 WebSocket 运行时；服务有消息时立即结束等待请求。
- Session 目录只保存 ID、标题、所属设备、最后更新时间和在线状态。所属设备首次连接及创建、重命名、删除 Session 时更新目录；离线仍保留上次目录。

## 消息流程

1. 控制端打开远端 Session，向所属设备请求分页面历史快照。所属设备从自己的 MaiAgent 存储读取，并经同步服务回传；控制端按原消息、片段 ID 渲染和本地缓存。
2. 所属设备在本地消息或工具状态变化后发送带序号的可见增量。控制端记录最后已收到的序号；断线重连后请求缺失部分。若所属设备不能提供完整增量，则重发快照。
3. 控制端发送操作时附唯一命令 ID、所属设备当前连接代次和目标 Session ID。服务仅将同账号且目标在线的操作投递给目标设备。所属设备持久化去重结果，再调用原有 MaiAgent 操作入口；确认与执行结果返回控制端。
4. 同一 Session 的变更在所属设备排序。正在运行的轮次不被另一台设备并发插入新提示；停止、权限决定和问题回答按现有 MaiAgent 状态处理。多台控制端会看到同一最终结果。
5. 图片、视频等大文件只在用户需要上传、打开或下载时传输。服务按有界分块转送，不保存文件；本机绝对路径永远只在所属设备解释。

### v1 设备消息格式

协议版本体现在 `/v1/session-sync/` 路径；传输层当前使用 HTTPS 长轮询。
一条发往所属 Mac 的文字操作形如：

```json
{
  "to_slot": "mac",
  "to_login_session_id": "当前 Mac 登录会话 ID",
  "client_message_id": "每次操作唯一的随机 ID",
  "session_id": "ses_...",
  "kind": "command",
  "payload": { "action": "prompt", "text": "继续刚才的编译" }
}
```

`history_request`、`history_page`、`event` 与 `command` 共用收件人、发送人和
消息编号。收件端 `poll` 取得可见事件后按稳定消息 ID 合并，再 `ack`；服务端的
`send` 成功只表示消息已进入目标设备的临时信箱，不表示 Agent 已执行。执行状态
必须由所属设备另外回传。消息正文和事件在确认或过期后删除，30 天的去重收据
只保留消息哈希和路由元数据。

## 失败和安全边界

- 所属设备心跳超时、睡眠、进程退出或登录会话失效时，目录标为离线，新的执行操作立即失败；服务不替用户排队执行过时任务。
- 服务只接受已有 MaiChat Bearer 会话，逐次核验账号和登录名额；登出、被替换或账号停用后拒绝新消息，并断开旧设备连接。
- 服务不在日志写会话正文、文件内容、账号访问令牌、模型凭据。消息大小、文件分块、待确认队列和等待时间均设上限；超限明确返回失败，客户端可从所属设备快照恢复。
- 客户端重试必须复用命令 ID。带副作用的 `command` 在首次取件时标记为已投递，
  之后不会自动再投递。若取件响应丢失，状态应显示「是否执行未知」；用户查看所属
  Session 历史后再决定下一步，不能自动发起另一轮付费任务。
- 可见事件和历史页在确认前可重复投递，接收端按稳定 ID 合并。服务确认投递不等于
  工具已经执行；界面分别显示送达、开始执行、完成或失败。去重收据不含正文，
  保留 30 天。

## 验收顺序

1. 服务端：同账号跨设备目录、跨账号隔离、无凭据拒绝、登录名额替换、离线失败、重投去重、断线补齐及重启恢复。
2. Mac 与 iOS：一台 Mac 创建真实本地 Session，iPhone 在不同网络查看历史、发无付费提示、看增量、停止/审批；Mac 断线重连后不重复执行。
3. Windows 与 Android：相同流程和跨四端互看、互控；验证移动端作为所属设备时前后台状态的真实边界。
4. 后端部署：在阿里云现有 ECS 增加独立进程和 Nginx 路由，核对实际运行版本、健康、鉴权及不代理模型；随后才更新对应客户端。
