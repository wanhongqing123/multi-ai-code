# MaiChat 多端 Session 群消息协议（2026-10-23 修订）

## 群组和成员

- 一个 MaiChat ID 对应同一账号。`ios_phone`、`android_phone`、`tablet`、`mac`、`windows` 是该账号的设备槽位；同一槽位只保留当前登录设备。
- 每个创作中心 Session 是一个独立群组，群组键为「账号 ID、所属设备槽位、MaiAgent Session ID」。所属设备保存可执行的 Agent 状态并直接调用模型供应商；其他成员可查看同一份群消息。
- 登录会话 ID 只用于将命令和通知送到当前设备，不能作为群组或历史消息的身份。旧登录被替换后，旧连接不能继续操作。
- 服务端不是模型代理：不保存模型密钥，不调用或转发模型 API、流式响应或媒体生成字节。

## 正式数据路径

1. 所属设备将本地 Agent 的可见消息按正式 `msg_...` ID 发布到 Session 同步服务。服务端用账号、所属槽位、Session ID、消息 ID 做唯一键，在 SQLite 中保存正文和当前版本。待处理权限及提问也作为群组状态保存。媒体只保存安全的可见元数据，不上传本机绝对路径或媒体字节。
2. 服务端将发生变化的群消息经已有 WSS `inbox` 分发到该账号的其他在线槽位。每个设备按正式消息 ID 更新同一条记录；未在查看该 Session 的设备可在以后从服务端读历史。一个设备确认收件不影响其他设备的收件箱。
3. 发消息的客户端先在自己的界面显示暂存消息，再用所属设备执行回执中的正式用户消息 ID 更新这一条。所属设备也在自己的界面显示它，并把正式用户消息及新生成的 AI 消息发布到群组。不存在根据文字或时间猜测重复消息的规则。

图片、视频、音频及文件沿用同一命令与历史 ID：发送端在独立会话附件空间
`session-attachments/<账号>/` 直传私有 OSS，命令只携带 `attachment_id`。
所属设备按账号与 `owner_slot:session_id` 核对归属，
获取短期签名读取 URL 后下载到该 Session 的本机工作目录，再按媒体类型交给
Agent；完整媒体字节不进入同步服务或模型代理。所属设备将附件 ID 和安全文件名
绑定到正式用户消息，群组持久历史保存引用；旧快照更新同一消息时保留该引用。
其他设备打开历史时重新签发读取 URL，不能把 60 秒 URL 或本机路径当持久记录。
用户删除 Session 后，所属设备请求独立附件空间清理该房间；个人云盘列表和
10 GB 配额不包含会话附件。
4. 首次打开群组从服务端取最近 10 条，上滑以 `before=<最旧消息 ID>` 分页取更早的 20 条。所属设备离线时历史仍可读取；执行新命令需要所属设备在线。断线重连再读最新页，补齐临时 WebSocket 通知可能遗漏的记录。
5. 所属设备登录后优先发布最近页，再限速回填已有长会话的旧页。删除本地 Session 后，所属设备调用 `room-delete` 删除服务端该群组的消息及状态。账号注销的运维清理脚本也删除 `sync_room_messages` 与 `sync_room_state`。账号切换不会把新账号的记录写入旧群组。

## WSS 操作

客户端请求形如 `{ "id": "请求 ID", "op": "操作名", "body": {} }`，服务端以相同 ID 返回 `response`；服务主动推送 `catalog` 和 `inbox`。连接前必须用 MaiChat Bearer 鉴权，并先发 `presence`；此后约每 15 秒上报目录与在线时间。旧的 `history_request`/`history_page` 设备间取历史方式不再使用。

| 操作 | 方向 | 用途 |
|---|---|---|
| `presence` | 设备 → 服务 | 当前登录设备、名称和本地 Session 目录 |
| `catalog` | 设备 → 服务 | 获取同账号各设备 Session 目录 |
| `history` | 设备 → 服务 | 从服务端按群组与游标读取已保存消息 |
| `publish` | 所属设备 → 服务 | 保存正式消息和权限/提问状态并通知群成员 |
| `send` | 控制端 → 所属设备 | 发送带唯一命令 ID 的 prompt、stop、权限决定等操作；执行结果走 `event` |
| `ack` | 收件设备 → 服务 | 确认本设备临时信箱中的通知 |
| `room-delete` | 所属设备 → 服务 | 删除本地 Session 对应的服务端群组记录 |
| `reauth` | 设备 → 服务 | 在同一 WSS 连接上续权 |

`send` 返回 200 只代表服务端收到了命令，不能当作 Agent 执行成功。带副作用的命令首次交付后不自动重放；若执行回执丢失，客户端提示状态未知并从群历史核对。临时信箱可重投只读消息，客户端确认一批后服务端继续推下一批；持久消息表是历史来源。当前帧上限 96 KiB，单条持久消息上限 48 KiB，临时信箱分块 24 KiB，连接速率上限每分钟 600 帧；超出消息上限应明确报错，不能悄悄截断文字。发布端只提交内容发生变化的消息，长历史回填限速。

## 已验证范围与交付边界

- 本地服务端测试覆盖账号隔离、三个槽位独立收件、共享分页、45 条跨页无缺口、重启保留、删除群组和旧登录替换。
- Mac Qt 定向测试覆盖所属设备发布消息、旧页回填、远端面板先显示自身发送内容并按正式 ID 更新、实时房间通知、重连补齐。
- iOS 模拟器正常 App 使用本地测试账号、假模型及真实 WSS 验证了共享群消息和远端命令。Android Debug 构建与共用移动 Agent 原生测试已通过；Android 真机、Windows 构建及生产服务部署需另行验收。
- 本地源码协议尚未部署到阿里云；用户当前安装的旧桌面包及线上服务仍使用旧协议，不能与本地新客户端混用。统一更新服务和各端后再做真实多设备验收。
