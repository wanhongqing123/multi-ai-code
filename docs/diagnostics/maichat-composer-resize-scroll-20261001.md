# MaiChat 拖大输入框后最新消息被遮住（2026-10-01）

## 现场与复现

- 用户提供约 10 秒的 Windows 桌面视频：向上拖动 IM 输入框上边界时，编辑框变高、消息区视口变矮，原本在底部的最近消息逐渐离开可视范围。
- 用 30 条消息构造最小复现，先滚到底，再分五步向上拖动手柄。修复前释放后的滚动值为 `1365/1413`，没有跟上增加的滚动范围。
- 此问题与先前的拖拽光标残留不同；光标清理提交不能修复消息滚动锚点。

## 根因与修复

- 消息新增时已有“接近底部则贴底”处理，但 `QScrollArea` 因输入框拖动而缩小时没有保存拖动前的阅读位置。滚动范围增加后，滚动值仍留在旧位置。
- 在手柄按下时记住是否位于消息底部和当前会话；仅在原本贴底时，拖动期间随滚动范围变化异步滚到新底部。释放、隐藏或失去鼠标抓取时断开临时连接；异步回调核对会话，避免影响切换后的会话。
- 原本在阅读历史消息时不启用贴底跟随。AI 助手的 `MarkdownView` 已独立处理缩放时的贴底状态，此次只改普通 IM。

## 验证与边界

- `composerResizeKeepsLatestMessageVisible` 覆盖逐步拖动和释放后的滚动位置、最新消息可见性；修复前失败，修复后连续五次通过。窗口布局测试 136/136 通过，Windows 桌面构建通过。
- 早期测试在布局重排期间遍历消息行出现偶发崩溃；改为拖动期间检查滚动值，结束后再检查消息行，测试稳定。没有证据将该测试崩溃归因于产品中的 Qt 回调重入。
- 测试验证的是源码构建；旧安装版不会自动更新。交付时必须核对用户实际运行的可执行文件。
