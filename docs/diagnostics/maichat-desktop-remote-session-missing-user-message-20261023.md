# Desktop 操作 iPhone Session 时漏显示本机消息

- 现场：2026-10-23，macOS 26.4。用户在 PC 创作中心打开 iPhone Session，发多条“你好”；iPhone 显示了用户消息，PC 远端面板未显示。现场运行 `/Applications/MaiChat.app` 2.2.11，本轮未停止或替换。工作树基线提交 `8ac971d3104ae447f965e8fb6ea0c0d479e4f248`，另有同期未提交任务改动。
- 复现与根因：旧 PC 面板打开时读最近 10 条，之后每 5 秒只读最新 1 条。一个 Agent 回合先落 user、再落 assistant，轮询经常只取到 assistant；发送端也没有先把自己的消息加入远端面板。iOS 原先没有主动发布本地 Agent 变化。针对 user+assistant 的旧轮询测试先失败，实际只取 1 条。
- 产品要求：同一 MaiChat ID 下，一个 Session 是一个群组，`ios_phone`、`mac`、`windows` 等槽位是成员。每个人看同一份服务端消息记录；所属设备运行 Agent，服务端保存正式消息并通过 WSS 分发。发送者先显示自己的暂存消息，所属设备回传正式 ID 后更新同一条；不用文字和时间猜测重复消息。初次读最近 10 条，上滑读更早的 20 条。
- 修复：服务端增加 `sync_room_messages` 和 `sync_room_state` 持久化表、`publish`、`history`、`room-delete` 操作。只有所属设备可发布或删除群记录，所有同账号槽位可按页读取。正式消息变化给每个在线槽位独立入信箱；一个成员的确认不影响其他人。PC/iOS/Android 从服务端读历史，所属设备上传 Agent 消息和权限状态；旧设备间 `history_request/history_page` 路径已删除。离线时仍可读群历史，新命令仍要求所属设备在线。三端后台限速回填已有本地长会话，删除 Session 同步清理群记录。服务端不代理模型请求或媒体字节。
- 验证：服务端测试通过账号隔离、三槽位独立收件、45 条跨页、重启保留和群组删除；账号注销清理测试确认持久群消息与状态一同删除。Mac Qt 面板验证发送端立即显示、正式 ID 更新、房间广播与重连补页；桌面所属设备的旧页回填及本地删除触发服务端群组删除的定向测试通过。iPhone 17 Pro 模拟器正常 App 使用本地测试账号、假模型和真实 WSS 验证了 Mac→iPhone 发送及用户/AI 两条正式群消息回传；反向 iPhone→假 Mac 会话的历史、发送与拒绝草稿恢复也通过。Android Debug 构建通过；移动共用适配层原生测试在 Android 模拟器通过。
- 边界：iOS 本地测试账号的腾讯 IM 还会出现与 Session 同步无关的参数错误提示。Windows、Android 正式 App 与真实多设备生产环境尚未进行本轮新协议验收；阿里云运行的服务和当前安装的 2.2.11 仍是旧协议。新服务与新客户端需作为一组部署，不能宣称已上线。
