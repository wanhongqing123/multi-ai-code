# 多端会话红色超时提示与 Desktop 删除入口回归

- 现场：2026-10-23，iPhone 14 Pro Max 的 MaiChat 2.2.3 (109) 在 Mac 所属 Session 发送“你好”后出现“送达状态未知”“设备同步操作状态未知”红字；Mac 2.2.13 测试包的本机会话列表没有可见的删除入口。线上同步服务为当天部署的群消息协议，Mac 正进行历史回填。
- 服务端根因：`session-sync-service.js` 的待投递查询对事件只检查未确认，不检查此前是否已经推送。每次发新消息、确认其他消息或上报在线都会唤醒 WebSocket，反复推送相同的前 8 个事件。iOS 客户端把这些推送加入队列，再逐条处理并确认，批量回填时队列被重复事件占满；新发送请求没在 15 秒内得到响应。生产库当时有数十个 Mac→iPhone 未确认事件，近期没有 iPhone→Mac 命令收据。这个超时提示并不证明消息已被对端执行。
- 最小回归：改动前本地测试两处稳定失败：第二次读取同一未确认事件预期 0 条，实际 1 条；已有 12 条群事件且首批未确认时第二批预期剩余 4 条，实际再次返回前 8 条。WebSocket 测试新增再次上报在线后的重复推送断言。
- 修复：事件读取时记录 `delivered_at`，同一连接 30 秒内不重推；未确认的事件在超时后可重投，断连或服务重启后清除其投递时间以便新连接立即补齐。命令保留首次投递后不自动重放的既有规则。回归由红转绿，服务端 12/12 测试通过。
- 线上更新：部署前把服务文件和 SQLite 在线一致性副本保存到 `/var/lib/maichat-session-sync/backups/inbox-20261023-aJwHP4/`，副本 `quick_check=ok`。只更新 `session-sync-service.js` 和 `session-sync-store.js`，线上 SHA-256 分别为 `8e15ae133e6ecfe73c26d5101a8adc0d47b212a605a11364f37e1bb2e3555bae`、`50f4440d24829c2b7258d74f985d8955e2bb3ad1cdfc57766917189ecb712d71`。重启后同步服务 `active`、数据库 `quick_check=ok`、错误日志为空；观察时待确认信箱为 0，iPhone 最近心跳约 2 秒。尚未由两台真实新版 App 重新发送并确认同一条消息。
- Desktop 根因：`AgentSessionList` 只绘制会话、选择会话，完全没有删除菜单或信号；MaiAgent 核心原有 `MaiDeleteSession`，但普通界面从未调用。新增本机会话行右侧可见 `⋯` 与右键菜单的“删除对话”；主窗口确认后调用核心删除，忙碌会话要求先停止。已选会话被删后沿现有会话结构事件恢复到有效会话。定向 Qt 测试覆盖菜单点击、信号、选中会话删除后的恢复，实际列表和菜单截图已查看。
- 预防：把“未确认时再次推送、超过单批的排队、重连后重投”作为同步协议固定测试；把“新建、切换、删除及菜单打开后实际画面”作为 Desktop 发布前验收。客户端与服务端协议更新必须一起用真实设备验证，记录安装包版本、进程路径和服务文件哈希。未做真实双端发送前，不宣称群消息功能已完整验收。
- 最终 Mac 测试包：`MaiChat/desktop/dist-session-room-20261023-v2214-final/MaiChat-macos-arm64/MaiChat.app`，版本 2.2.14，主可执行文件 SHA-256 `555e917b3d3ccea2f828aa93b0aec94f2b22f62807c6fbe99f8c03079b7e93c0`。本机已选和非已选会话菜单点击测试、删除后会话恢复测试、菜单展开测试通过；后续修正非当前行 `⋯` 的命中处理，不再错误切换列表选中项。Desktop 会话面板与主窗口布局 CTest 2/2 通过；打包后深度签名和独立 `--smoke` 通过，UI 截图已查看。未替换用户现装 App，旧候选包已清理。
