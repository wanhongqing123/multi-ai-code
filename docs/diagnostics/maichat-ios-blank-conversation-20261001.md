# iOS 会话进入后消息区短暂空白（2026-10-01）

## 现场与复现

- 用户的 15.295 秒 iPhone 录屏显示：打开 `mac-multi-ai-code` 会话后，
  标题与输入框正常，但消息区约 4–5 秒没有消息；返回列表后再次进入，
  又出现约 3 秒空白，然后消息显示。空白期间右侧可见消息滚动条。
- 视频为 1290×2796、HEVC 画面；不能从录屏读取 App 构建号或设备日志。

## 定位证据

- `ChatView` 的会话消息数组已经交给 `MessageListView`；标题和输入框持续可见，
  消息区域的滚动条说明并非整个页面未创建。
- iOS 消息列表使用正常方向 `LazyVStack`。原 `MessageScrollPositionReader` 仅在
  **视口尺寸**改变且仍跟随最新消息时重新定位；Markdown 内容在首次进入时
  由占位高度变为实际高度，**内容尺寸**变化却未触发定位修正。
- 在模拟器创建 80 条会延迟变高的消息并退出再进入，原代码下最后一条消息
  的顶部停在 640 像素视口下方约 2400 像素，`nearBottom=false`。这是同类
  空白视口的可重复最小用例，但没有用户设备日志，不能证明现场的全部耗时
  都来自这个原因。

## 修复与验证

- 当内容尺寸变化、列表仍在跟随最新消息且用户未手动浏览历史时，也安排
  一次异步的底部定位；定位目标改为最后一条真实消息行，避免只定位到
  LazyVStack 末尾的透明占位元素。搜索定位与用户主动上滑仍保持优先。
- 同一模拟器用例修复前失败、修复后连续两次进入均通过。相关滚动测试
  验证发送后定位、历史阅读、取消返回手势和短会话布局没有回退。

## 未验证边界

- 用户 iPhone 当前在开发机上显示为离线，尚不能读取其应用诊断日志或
  安装修复构建复测现场。旧包不会自动获得这项修复。
