# Mac 所属 Agent Session 漏显示 iPhone 发来的用户消息

- 现场：2026-10-23，用户在 iPhone 上打开 Mac 所属 Session，发送「你好」。iPhone 显示该用户消息，Mac 创作中心当前会话显示 Agent 回复，却没有「你好」。截图来自当晚实机操作。工作树基线 `8ac971d3104ae447f965e8fb6ea0c0d479e4f248`，桌面测试源码与构建含未提交改动；没有替换正在运行的 App。
- 复现：在 Mac 桌面端打开本机 Agent Session；让 `DesktopSessionSyncHost::applyCommand` 按 iPhone 下发的 `action=prompt,text=你好` 入口执行。`user_message_id` 非空、Agent 本地历史已有用户消息，但正在打开的 `MarkdownView` 不含这个 ID。新 `AgentPanelSessionTest::remotePromptAppearsInOpenOwnerSession` 在修复前失败，断言 `view->contains(userId)` 为 false。
- 根因证据：`MaiAgent::submit(MaiSendPrompt)` 先将 User 消息写入存储并发出 `MessageUpdated`，再建 Assistant 消息并运行模型。`AgentController::onEventQueued` 原先忽略 `MessageUpdated`；`AgentChatPanel::onSend` 仅在本机按钮路径手工调用 `appendUserBubble`。远端命令绕过本机按钮，所以用户消息不进入当前面板；Assistant 的 `MessagePartDelta` 经 `textDelta` 正常显示。服务端群记录与 iPhone→Mac 命令收据已由另一排障者只读核对，连续 User 与 Assistant 均存在，因此问题限定在 Mac 本地渲染。
- 修复：Controller 遇到已落库的 User `MessageUpdated` 发 `userMessageAdded(sessionId,messageId)`；面板仅对当前会话按真实 ID 读取并增量呈现。按钮路径也使用这份存储消息呈现；渲染过的用户 ID 在当前视图内只绘一次，切换会话后按存储重建。图片、视频、引用与文字沿用同一个渲染函数，避免本地与远端两套 UI 逻辑。
- 验证：新增远端命令的红→绿测试，以及本机按钮发送、异步消息事件、切换会话后均只有一份用户可见文本的回归。macOS 26.4 arm64 Release 桌面测试目标和 `MaiChat.app` 重链通过；`AgentPanelSessionTest` 全部 43/43、`DesktopSessionSyncHostTest` 全部 16/16。`build-release/bin/MaiChat.app/Contents/MacOS/MaiChat --smoke` 退出码 0，日志确认执行路径和 OpenSSL 可用。以原生 Cocoa Qt 插件运行远端命令测试并亲看 `/tmp/maichat-remote-user-ui.png`，当前会话右侧出现一份「你好」用户气泡。`SilentModel` 的空 Assistant 仍附带一个原有的「引用」动作，因此测试按可见用户文本和持久 ID 判断一次显示。与删除确认修复一起封装的独立包为 `MaiChat/desktop/dist-session-room-20261023-v2215/MaiChat-macos-arm64/MaiChat.app`，版本 2.2.15，主可执行文件 SHA-256 `ebc4c116377261405ebbf1e597ceb5d6588863aa22cc2b7e7550c499869169b0`；深度签名和独立启动检查通过，Desktop 三组 CTest 3/3。真实 Mac/iPhone 双端操作与新包替换尚未进行。
- 边界：此改动仅在 Mac 客户端渲染；服务端无需为这个缺口再改协议。iOS 侧能显示其自己发送的消息，本轮未修改 iOS。
