# macOS 登录二维码与账号请求在 DNS 故障时超时

## 现场

- 2026-10-30 11:15 后，macOS 27.2 正在运行 `/Applications/MaiChat.app` 2.2.31，PID 646。用户报告登录页停在“正在生成二维码”，账号密码登录也失败。预期是生成二维码或给出可重试的错误。
- 现场系统 DNS 指向 Shadowrocket 隧道的 `198.18.0.2`；对账号域名的系统解析超时。公共 DNS 查询给出地址后，临时指定该地址但保留原域名、TLS 证书和主机名校验，账号 `/api/v1/auth/me` 返回预期的未认证 401。该测试不证明隧道故障的内部原因。
- 原 2.2.31 定向账号探针 30 秒后报 `Timeout was reached`。虽然传输层设置了 10 秒连接与 15 秒整体超时，故障的系统 DNS 解析清理实际拖延了返回。不能仅由截图判断当时画面停留的总时长。

## 修复与边界

- macOS 账号请求先使用无凭据 GET 探测系统线路，失败时并行探测阿里 DNS 和 Cloudflare DNS 的 DNS-over-HTTPS 备用线路，以先成功的线路直连。两者均验证 DNS 服务 TLS 证书；业务域名仍动态解析，连接业务服务时继续验证原主机名和证书，不改变系统 DNS、代理或 hosts。
- 系统探测放在独立线程，等待上限 2.5 秒；故障系统解析线程晚退出时只持有自身数据，不阻塞备用线路。探测成功线路缓存 60 秒，传输失败后失效。只有确认线路后发送一次真实 POST，绝不重放登录或二维码创建请求。
- 该修复覆盖通过 `DesktopAuthClient::request` 的账号 HTTP，包括登录、账号操作及模型 API Key 领取；直接访问模型供应商、IM 图片下载、Session WebSocket 和其他平台是独立链路。备用 DNS 有第三方域名查询，依用户明确要求在系统解析失败时启用。

## 验证

- 修复候选基线 `cb36bda0f`；系统 DNS 故障未恢复时，正式无凭据账号 GET 测试通过，7.3 秒；此前同一测试为 30 秒超时。
- 正式二维码创建、PNG 校验与取消 9.98 秒通过；未登录账号。实际 `LoginDialog` 通过相同故障环境在 8.4 秒显示二维码，人工查看后关闭，测试确认取消。截图保存在私有临时位置，检查后已删除。
- 本地 HTTP 替身保持连接不应答，15 秒后登录窗显示网络错误和重试，且超时前后只创建一次请求；手动点击重试后正常显示二维码。
- 两个公共 DNS 均以独立 curl DoH 实测可以解析并访问正式无凭据端点。并发方案中哪一个率先返回取决于实际网络；尚未模拟屏蔽其中一个服务的产品级环境。
- 上述使用定向构建测试。安装版 Mac App 在验证时仍是旧 2.2.31；只有更新实际安装并核对运行路径后才能认为用户环境已更新。
