# macOS 远程 IM 文件下载失败

- 现场：2026-10-30，`mac-maichat` 收到 `mac-multi-ai-code` 的两条时光胶囊 Markdown 文件消息后，界面均显示失败；同一会话文字正常。运行程序为 `/Applications/Multi-AI Code.app` 0.1.97，源码基线 `c748572cc`。
- 复现与证据：只读接收端账号库，两条文件均已入库，状态 `failed`、错误 `fetch failed`，附件没有本地路径。对各自原始附件地址，直连在 DNS 解析阶段超时，经过本机代理均返回 HTTP 200；隔离 Electron 使用 `net.fetch` 取回其中一个附件，大小 1,263,633 字节。未在记录中保存地址、签名或文件内容。
- 根因：文件入站 IPC 调用 `cacheRemoteImFile` 时没有注入 Electron 网络栈，默认使用不遵循系统代理的 Node `fetch`；同类图片链路此前已修复。连接成功只能说明 IM 消息传输正常，附件另走下载链路。
- 修复：入站文件使用 `net.fetch`。对历史失败文件增加原消息重试，限当前账号的入站失败记录及原始项目和 URL；完成前再次检查账号代次、记录状态和地址，不重新投递 Agent。同一消息重试互斥，大小限制与首次文件接收一致；签名失效时保留原失败状态。
- 验证：2026-10-31，隔离 Electron 隐藏窗口渲染真实 React 文件卡片，用临时 SQLite、模拟 IPC 和真实重试核心测试。模拟 HTTP 403 后仍为失败并显示错误；改用现场地址后快速连点两次仅执行一次下载，记录恢复为 `received`、文件 1,263,633 字节、Markdown 卡片可预览，测试环境无 Agent 投递入口。隔离数据库和下载文件已删除。定向 Vitest 30 项通过，涵盖签名失效、账号变化、错误项目与 URL、已恢复后重复重试及 5 MiB 以上文件的大小限制；TypeScript 类型检查和 `git diff --check` 通过。
- 边界：隔离测试复用了组件、缓存与存储实现，IPC 包装为测试环境模拟；运行中的安装版和真实账号数据库未修改，安装版完整聊天界面尚未验证。旧附件地址失效后需要发送方重发。

- 发布准备：按用户指定版本号 2.2.5。完整远程 IM 回归 45 个文件通过，465 项通过、2 项跳过；类型检查、行宽检查及应用构建通过。发布包的最终校验记录随 GitHub Release 附件提供。
