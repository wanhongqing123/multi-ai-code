# macOS 远程 IM 图片下载失败

- 现场：2026-10-30，用户在 macOS 的 Multi-AI Code 远程 IM 中收到 iOS 图片后，图片显示下载失败，消息提示 `fetch failed`。运行应用为 `/Applications/Multi-AI Code.app`，源码基线为 `f2709a861`。
- 排查：当前账号数据库中的多条入站图片记录状态为失败、本地路径为空；之前同一腾讯 IM 图片域名的消息曾成功下载。图片下载由 Electron 主进程 `cacheRemoteImImage` 发起，原先默认使用 Node 的全局 `fetch`。
- 证据：对现场失败图片的同一签名地址，直接请求在 DNS 解析阶段超时；经当前 macOS 系统代理请求返回 HTTP 206。隔离的 Electron 进程识别到系统代理，使用 `net.fetch` 返回 HTTP 200 和非空 PNG。未记录图片地址、签名或图片内容。
- 修复：入站图片下载由 Electron 网络栈执行，遵循系统代理；独立 Node 调用仍保留原有默认行为。历史失败图片通过消息内重试恢复本地附件，不重新发送给 Agent；若原地址失效，重试仍会失败。
- 验证：独立 Electron 网络请求已对现场失败地址成功。使用同一地址、隔离数据库和隐藏 Electron 窗口点击重试，实际调用图片重试实现，原消息状态由失败变为收到、下载到非空 PNG；隔离程序未连接 Agent 投递入口，临时数据库和图片已删除。图片缓存、重试、消息存储、preload、界面定向测试共 48 项通过，TypeScript 类型检查与生产构建通过，产物中确认存在新的 IPC 实现。
- 边界：隔离窗口用于验证点击、IPC 和恢复核心，尚未在安装版的真实聊天界面完成端到端验证。用户正在运行的安装版未替换；需要部署新构建并重启应用后修复才会生效。旧图片的签名地址过期时仍可能无法恢复。
