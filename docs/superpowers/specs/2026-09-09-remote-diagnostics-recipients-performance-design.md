# 远程排障接收人与性能现场补全

## 问题与已确认原因

用户在 A 的 MaiChat 中打开与 B 的会话，收集 A 与 B 的现场，希望报告可以发给 B，也可以交给另一个好友 C。B 同时是被采集端和排查者是有效场景。

桌面端 `MainWindow::requestRemoteDiagnostics` 将 `contact.userId == peerId` 的好友排除，导致 B 不出现在列表中。控制器本身允许接收人与被采集好友相同。iOS 的列表仅排除登录账号，没有排除 B。

iOS 已记录 composer-edit、composer-text-mutation、composer-update、composer-layout、composer-height-queue、asr-main-actor-wait 和 main-runloop-delay。远程导出要求账号、好友归属，性能事件没有这些字段，因而被过滤；字段白名单也没有性能统计字段。桌面 A 端报告仅包含消息和附件证据，没有结构化 UI 性能采样。

## 方案选择

采用“修复接收人选择，并补全有界的结构化性能记录”。仅修复接收人无法满足卡顿排查；直接传整份原始日志则难以控制其他会话内容、报告体积和敏感字段，也不能补上未采样的信息。

## 接收人与发送行为

- A→B 采集，合并 A+B 后可发送给 B 或好友 C；列表保留当前会话好友，并标明当前会话。
- 报告包含的现场由 A 与 B 决定，选择 C 不会改为采集 A 与 C。
- 保留确认动作、接收人锁定、账号切换失效、取消及发送结果不确定的处理。
- 用户截图中的“自己”对应会话对方 B。本次不新增给登录账号 A 自发消息的功能。
- 不自动向任何真实好友发测试消息；协议、控制器和 UI 测试使用测试客户端。

## 性能现场

### iOS

将已有输入处理、文本修改、布局、布局排队、SwiftUI 更新和主线程延迟统计纳入远程报告，保留次数、慢样本数、阈值、最大值和平均值。增加明确的启动与账号上下文，账号切换时完成上一段统计，避免把跨账号累计值归给新账号。进程级性能与当前会话事件分别标注，不能将整个应用的延迟误称为该会话导致。

纳入当前账号历史读取/写入耗时与失败、消息展示和滚动相关已有事件。调整事件及数值字段白名单；保留脱敏要求，不导出草稿、按键内容、其他好友消息正文、凭据或任意文件路径。

### Desktop MaiChat

增加低开销、容量受限的性能记录器，记录 UI 事件循环延迟以及输入处理、消息列表更新/布局、历史读取与写入、图片解码等关键操作的耗时。采用单调时钟计算耗时；事件附带采集时间、进程/账号上下文、采样次数及聚合值。应用挂起/恢复时重置延迟基线，不将后台休眠计为 UI 卡顿。

耗时记录不进行同步磁盘写入或逐键日志输出；输入路径仅累计数值，周期汇总。慢操作可以单独记录受控的事件类型、时长和条目数量。

### B 端与合并

审计 MultiAICode 导出和 iOS/Qt 接收端的字段过滤，确保支持的性能字段在采集、传输、再次清洗和合并后仍保留。B 端已有消息路由、SDK 回执、进程生命周期及内核来源继续保留。没有实现的性能源明确标为 unavailable，不输出假的零耗时。

## 完整性与解释边界

报告列出各类来源的支持状态、实际时间范围、事件数量、容量截断/丢弃情况和采样阈值。区分未采样、未触发、源缺失、日志截断和采集失败。沿用近期 30 分钟的默认范围和文件体积限制，不能承诺无限历史或任意故障均可由一份日志确定根因。

事件循环延迟证明该段响应迟缓，不能单独证明哪个调用阻塞；row-presented 证明视图挂载，不能证明像素已经显示。报告写明当前是否有调用栈证据；本次不增加持续全量调用栈或屏幕录制。历史上已经发生、但当时未采样的卡顿无法补采。

UI 说明相应更新，明确收集消息收发、输入/界面响应、存储及附件处理等诊断信息，并标出缺失来源。

## 验证要求

1. Desktop 真实菜单点击测试：B 可搜索、选择、确认；唯一好友为 B 时仍可采集；取消不发送。
2. 控制器测试：A+B 合并发送给 B；A+B 合并发送给 C；切换聊天不改变接收人；账号变更不发送。
3. iOS 导出测试：性能和存储统计保留；其他账号/其他会话记录隔离；敏感文本不进入报告；数值字段经过验证。
4. 性能记录器测试：可注入时钟，验证阈值、聚合、容量、前后台和账号边界，无依赖真实等待的脆弱测试。
5. 固定 A/B 报告夹具验证采集到最终 Markdown 的字段一致性和缺失/截断标记。
6. 运行相关 Swift/Core 测试、iOS 应用构建、Qt 相关测试及桌面构建；实际输入流畅度需要真机复现或采样，不以单元测试代替。

## 当前状态

已实现当前好友接收合并报告、iOS 性能/存储导出、Qt 有界性能聚合与字段传输。既有用户 iOS 签名工程配置未改动。

Qt 使用 2 秒聚合桶、4096 条上限，覆盖输入事件排队与回调、消息刷新/布局、历史读取/写入、图片解码与前台 UI 心跳延迟。仅在主窗口创建后采样，启动前历史载入尚未覆盖并明确标为 unavailable。B 端 MultiAICode 当前没有 UI 性能采样，报告明确标为 unavailable；原有生命周期、路由与 SDK 证据继续提供。

iOS 沿用现有输入与主线程采样；补充分页读取的等待耗时。主线程延迟日志最多每 2 秒一条；性能统计不包含调用栈。内存日志最多 2048 条，导出最后 1000 条另加覆盖说明；缺失不代表性能正常。丢弃计数从最近一次账号激活起累计。

验证：iOS 170 项测试通过；Qt 40 个测试程序分别验证通过（39 个 offscreen，视频预览补齐原 Git blob 夹具后使用 Cocoa 通过）；宿主诊断 13 项通过。完整 iOS 模拟器应用和 Qt 应用构建通过，TypeScript 检查通过。未验证 Windows 构建或真实 IM A→B→B/C 网络收发，未安装到用户手机或发布新版本。输入卡顿本身尚未通过真机采样定位。
